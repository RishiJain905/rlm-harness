## rlmh 1.0.0

v1 adds Harness²: tools for measuring a harness and tuning it from your own tasks. It also adds conversations and compaction, and a new contract for the `default` profile.

**The `default` profile** now runs rlmh's own contract, rlmh-1, with its own system prompt (D-256). It adds `scan()`, a reading recipe and a submit check (D-251), so the model hands more of a long input to sub-calls. On the v1 eval set's held-out split with DeepSeek V4.1 Flash, it passed as many tasks as 0.2.0's profile (17 of 23) at 1.86 times the cost. The tuner accepted no change to it. All numbers, and what they can't show, are in [the v1 results](https://github.com/RishiJain905/rlm-harness/blob/v1.0.0/documentation/v1/results.md). `training-v4`, the LoRA's profile, is unchanged.

**New**
- **Follow-ups.** In the interactive app, a question after an answer continues the same run: the same REPL, variables and workspace. The `conversation.follow_ups` setting turns this off. `rlmh run` and `rlmh batch` stay one-shot.
- **Compaction.** Long runs under `default` summarize their oldest turns before the model's window fills, rather than failing.
- **`rlmh eval`.** Run a profile on an eval set and grade it: read tasks, Python and web repo tasks, and GPU kernel tasks. It shows a price estimate first and spends nothing without `--go`. It also has `--max-usd` as a hard cap, `eval report`, `eval compare`, `eval ledger` and `--rerun` for transient errors. Runs stop at once when the account is out of credit.
- **`rlmh tune`.** Harness²'s offline tuner: model editors propose changes to a profile from earlier runs, probes test them, and a change is kept only if it beats the incumbent on the tune split. Estimate first; spends only with `--go`.
- **`/tune`.** An on/off switch, off by default. `/tune on` shows the estimate before anything can spend. While it's on, each new task you run is tuned in the background in a throwaway snapshot of your folder (your files are never touched), up to `tune.max_usd` (default $1). A kept harness becomes a `tuned-<date>` profile.
- **`/tuned`.** Switch between `default` and your `tuned-*` profiles.
- **`tune.model`.** The model the tuner uses, "same as root" by default; it's also a row in `/model`.
- **The experience library.** What `/tune` learns is written to a library that later tuning reads. `tune.library` (on by default) turns it off.
- **`tune.test`.** A test command `/tune` runs in its work copies: a tuned harness whose test fails where your own run's passed is dropped.
- **Skills and scripts in profiles.** A `default`-based profile can carry `skills/` (`skill(name)` in the REPL) and `scripts/` (D-233).
- **Thinking levels per model**, from `off` to `max`. The gateway sends the nearest level a model takes.

**Upgrading.** 1.0.0 speaks link protocol 2, so an installed 0.x engine isn't reused: `rlmh update` (or the next start) sets up the 1.0.0 engine.
